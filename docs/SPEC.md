# 整理HQ（SeiriHQApp）統合仕様書

## 1. 概要

「プロンプト交通整理アプリ」と「画像・動画管理アプリ」を、1つのAndroidアプリへ統合したもの。

2つは別テーマだが、設計上の骨格が同じため同居させる。

```text
共通の骨格

大量の対象
   ↓
1か所に集約
   ↓
AIが仮分類・提案
   ↓
ユーザーが最終判断
   ↓
必要な部品だけ組み合わせて使う
```

- プロンプト側は「テキスト部品」を交通整理する
- 素材側は「画像・動画」を交通整理する

対象が違うだけで、状態遷移・AI権限・ユーザー優先の原則は共通にできる。

---

## 2. 統合オントロジー

```text
SeiriHQ
│
├── Project                 ← 両機能の共通単位
│
├── Prompt
│   ├── FixedPrompt         最大30件・永続
│   ├── TemporaryPrompt     最大20件・一時
│   ├── CustomPrompt        保存しない
│   ├── PromptComposer
│   └── FinalPrompt
│
├── Media
│   ├── Image / Video
│   ├── Inbox
│   ├── Status
│   ├── Tag
│   └── MediaProject        Media N:M Project
│
└── AI（第2段階以降）
    ├── PromptClassifier    ①②③分類・重複・矛盾
    └── MediaClassifier     内容分類・タグ生成・重複・プロジェクト推薦
```

Projectを共通エンティティにしたことで、将来「このプロジェクト用のプロンプト」「このプロンプトで生成した素材」を同じIDで結べる。

---

## 3. 共通原則

元の2つの仕様書から、共通する原則だけを抜き出して統合ルールとする。

1. 対象はまず1か所（Inbox / プロンプト置き場）に入れる。
2. AIは提案し、確定はユーザーが行う。
3. AIの判断には信頼度を持たせ、低信頼度は確定情報として扱わない。
4. 明示的なユーザー指定はAI推論より常に優先する。
5. AIはユーザーが作ったもの（タグ・フォルダ・プロンプト）を勝手に変更・削除しない。
6. 原本（メディアファイル・元プロンプト）は自動で書き換えない。
7. 自動処理はデフォルトOFF。段階的に開放する。

## 4. 最小構成（v1.0 / Phase 0）

### 画面

```text
[プロンプト] [素材] [設定]
```

#### プロンプトタブ

- TOP：①固定 / ②個別切替 / ③任意入力 / 完成プロンプト / コピー
- ②は左右スワイプおよび ← → ボタンで高速切替、位置を `03 / 20` 表示
- ①一覧（最大30件）：登録・編集・削除・使用
- ②一覧（最大20件）：登録・編集・削除・使用・全削除（確認ダイアログ）
- 機能説明は50文字以内、入力中に文字数を表示
- 合成は空欄を自動除外し、余分な空行を作らない

#### 素材タブ

- 取り込み（複数選択）
- Inbox一覧（グリッド表示）
- 検索（名前・タグ・プロジェクト名）
- 状態フィルタ
- 素材詳細：状態変更 / プロジェクト紐づけ（複数可）/ タグ編集 / 一覧から削除

#### 設定タブ

- プロジェクトの作成・削除（両機能共通）
- 実装範囲の説明

### 権限

素材取り込みは SAF（ファイル選択）を使用し、`READ_MEDIA_IMAGES` / `READ_MEDIA_VIDEO` を要求しない。
選択したURIには永続的な読み取り権限を取得する。原本は移動もコピーもしない。

これにより、軽量なプロンプト側が重い権限を背負わずに済む。
MediaStore全体スキャンが必要になる段階（自動取り込み・重複検出）で、初めて権限を追加する。

## 5. データモデル（実装済み）

SQLite（`seirihq.db` / version 1）。両機能で1つのDBを共有する。

```text
prompt(id, kind['fixed'|'temp'], name, description, body, created_at, updated_at)
state(key, value)                       -- active_fixed / active_temp
project(id, name, created_at)
media(id, uri UNIQUE, kind, name, status, tags, added_at)
media_project(media_id, project_id)     -- N:M
```

- ③任意入力は永続保存しない（メモリ上のみ）
- タグは現状カンマ区切りのTEXT。Phase 1で `tag` / `media_tag` へ正規化する
- メディアは参照（URI）で保持し、物理コピーを作らない

```text
MediaStatus

PromptState

```

## 7. フェーズ計画

### Phase 0（v1.0 実装済み）

- 2機能の同居、共通DB、共通Project
- プロンプト管理・合成・コピー・②高速切替
- 素材取り込み・Inbox・状態・タグ・プロジェクト紐づけ・基本検索

### Phase 1

- タグの正規化（AIタグ / ユーザータグ / システムタグの3種別）
- プロジェクト詳細画面（素材数・未使用数）
- スワイプ交通整理（上=プロジェクト / 右=保留 / 左=アーカイブ / 下=削除候補）
- プロンプトセット（用途別の①②③組み合わせ）

### Phase 2（AI）

- プロンプト：①②③分類推奨、50文字説明生成、重複検出、矛盾検出、役割逆転検出
- 素材：内容分類、AIタグ生成、重複検出（Exact / Near / Similar）、プロジェクト推薦
- 信頼度：95%以上=自動、80〜94%=提案、80%未満=Inboxで確認
- 自動整理レベル Level 1 / 2 / 3（デフォルト Level 2）

### Phase 3

- 自然言語検索（両機能）
- Smart Folder
- ユーザー操作からの学習・個人ルール候補
- 動画解析（フレームサンプリング・音声・OCR）

## 8. 統合したことで生まれる導線（将来）

```text
プロンプトで生成
   ↓
出力画像・動画を取り込み
   ↓
同じProjectへ自動で紐づけ
   ↓
どのプロンプトから生まれた素材か辿れる
```

Phase 1以降で `media` に `source_prompt_id` を追加すれば、この導線が成立する。
分離した2アプリでは実現できない部分であり、統合の主な利点はここにある。

## 9. 技術構成

```text
Kotlin + Jetpack Compose（Material 3）
AGP 8.5.2 / Kotlin 2.0.20 / Gradle 8.9
minSdk 26 / targetSdk 34
SQLiteOpenHelper（アノテーション処理なし）
Coil（画像サムネイル）
GitHub Actions で assembleDebug
app/debug.keystore を固定（上書きインストール可）
```

Roomを使わずSQLiteOpenHelperにしているのは、スマホのみのビルド環境で
KSPやアノテーション処理のバージョン不整合を持ち込まないため。
